## 6. Account-linking + auth server routes

- [x] 6.1 Add `POST /api/link-accounts` route — authenticated (session cookie), reads `application_id`/`refreshToken` from `system_config`, calls `refreshIdToken` to obtain a fresh idToken, calls `linkAccounts` (the `redirectUrl` is a fixed constant inside the client, not read from `system_config`), stores the `psu_id_hash` **and the selected bank info** (`aspsp_name`, `aspsp_country`, `psu_type`) in the user session (needed by the state endpoint for the resume flow), returns `{ "authorization_url", "psu_id_hash" }` (spec ADDED: Account-linking endpoint)
- [x] 6.2 Add `POST /api/auth` route — authenticated (session cookie), **clears any stored `auth_error` from the user session at the start of the request** (the user is starting a fresh attempt — the old error must not follow them into the new attempt or appear in a subsequently opened tab), generates a `state` JWT containing the session ID, reads `redirect_url` from `system_config` (`enable_banking_redirect_url`), computes `valid_until = now + aspsp.maximumConsentValidity` (looked up from the ASPSP list), calls `startAuth` with `access = { balances: true, transactions: true, valid_until }`, returns `{ "url", "authorization_id", "psu_id_hash" }` (spec ADDED: Auth initiation endpoint)
- [x] 6.3 Extend the existing `GET /enable-banking-callback` route to handle auth returns: if `code` is present and `oobCode` is absent, **verify the session cookie** (same browser tab → cookie expected, unlike the email-link callback which may be a different device). On missing/invalid session cookie, **302 redirect to the BankTeller login page** (username/password login — not the Enable Banking email-link flow) and discard the `code` (single-use, time-limited). On valid session: decode `state` JWT to get session ID, call `authorizeSession(code)`. On success (200 — sole success indicator, no `status` field in the response), clear any stored `auth_error` from the user session (belt-and-suspenders — `POST /api/auth` already clears it), store `session_id` + `accounts[]` in the user session, serve SPA bundle. On failure (non-200 from `authorizeSession`, or invalid `state` JWT), **store the error reason as `auth_error` in the user session** (so the SPA can display it on the LinkingProgress screen with a "Continue to authorization" retry button via the `GET /api/onboarding/state` resume flow — the error is cleared when the user clicks the button, via `POST /api/auth`), serve SPA bundle (spec MODIFIED: Email-link callback route — auth callback handling).
- [x] 6.4 Add `GET /api/onboarding/link-status` route — authenticated (session cookie), calls `GET /application` on the control-plane API (fresh idToken via `refreshIdToken`), inspects `whitelisted_accounts[]` for a `psu_id_hash` match (stored from the link-accounts response), returns `{ "linked": bool }` (spec ADDED: Link-completion check endpoint). **Single on-demand check** (triggered by a user-clicked button), not polling.
- [x] 6.5 Add `GET /api/onboarding/state` route — authenticated (session cookie), inspects the **BankTeller user session** (ephemeral, tied to the session cookie) and `system_config` to return a structured response with **routing flags** and **display-only fields** (per D10): `{ "requires_relogin": bool, "linking_completed": bool, "auth_completed": bool, "auth_error": string|null, "selected_bank": object|null }` (spec ADDED: Onboarding state endpoint). `requires_relogin` = true if `enable_banking_refresh_token` is missing from `system_config` (sole re-login signal — the SPA never parses `auth_error` for routing). `linking_completed` = true if `psu_id_hash` is in the user session. `auth_completed` = true if `session_id` + `accounts[]` are in the user session. `auth_error` = stored error reason or null (display-only, ephemeral — dies with the session, cleared on new `POST /api/auth` attempt). `selected_bank` = `{ "aspsp_name", "aspsp_country", "psu_type" }` from the user session (stored by `POST /api/link-accounts`), or null if linking not completed — the SPA needs this to call `POST /api/auth` in the resume flow.
