## Why

Onboarding is complete, but the dashboard is still an empty welcome page: the user has connected their bank and then sees nothing of value. The first product feature delivers the core aggregation promise — all connected accounts and their balances in one place — backed by a balances sync engine so the data is always available (served from the database, not dependent on a live bank API), with connection health visible at a glance and a manual sync affordance. This also builds the minimal sync foundation (triggers, persistence, PSU-header policy) that the later transaction-history feature extends.

## What Changes

- **Balances sync engine (new)**: fetches account balances from Enable Banking and persists them. Three triggers: (1) login — one sync run, stale-while-revalidate presentation; (2) manual "sync now" — user-initiated, server-side debounced to max ~1/min (anchored at the last user-triggered run start; background runs don't arm the cooldown); (3) background timer — ~every 6h (named constant), no PSU headers, first run one full interval after restart. Each run also refreshes per-session consent data via `GET /sessions/{id}`.
- **PSU-header policy (new)**: PSU headers are attached to Enable Banking data-plane calls ONLY when a real user browser action (login, manual refresh, wizard import trigger) is the trigger. The background timer never sends PSU headers. No code path fakes PSU presence; PSU IP uses the same proxy-aware resolution as the login rate limiter.
- **Initial data import (new)**: the onboarding/connect wizard gains a final step that triggers `POST /api/onboarding/import-balances` for the newly authorized session (the user is present — real PSU context), observed via the `GET /api/accounts` in-flight flag. Gated by a one-shot `pendingInitialImport` session signal set by the auth callback; the run survives client disconnects. Failure offers retry or continue-anyway (degraded dashboard state).
- **Database (new tables + columns)**: `balances` (latest balance per account) and `sync_log` (per-sync-run record: type, status, timestamps) via a new SQLDelight migration; the same migration adds nullable `valid_until` + `logo` columns to `eb_sessions` (captured at authorization, `valid_until` refreshed every sync run). Deletion paths clean up dependent `balances`/`sync_log` rows. The `DatabaseFactory` version-inference ladder distinguishes the new schema for pre-migration-framework databases.
- **Enable Banking client (new methods)**: data-plane `getBalances(accountUid, psuHeaders?)` calling `GET /accounts/{uid}/balances`, and `getSession(sessionId)` calling `GET /sessions/{id}` (session status, consent expiry, account list).
- **Server routes (new)**: `GET /api/accounts` (accounts + last-known balances + per-bank health + consent expiry + global in-flight flag), `POST /api/sync` (manual trigger with debounce), `POST /api/onboarding/import-balances` (wizard import trigger).
- **Dashboard UI (replaces welcome page)**: hero total balance (EUR-first; grouped subtotals when mixed currencies — never a false combined total), account cards (bank + logo via existing proxy, name, masked IBAN, balance, bank-scoped consent status), metadata strip (per-bank last-updated badges + global refresh button + permanent "Add bank" control), degraded-state presentation (stale/error/rate-limited/never-synced), empty presentations (never-synced placeholder, zero-account hint, fetch-failure retry), and a 5-state visual state matrix per the designer consultation. No transaction display in this change.
- **Sandbox onboarding completion (new)**: account authorization is required for onboarding completion regardless of environment — sandbox apps skip account linking (a production-only entitlement) but must authorize one session before the dashboard. The resolver's sandbox auto-activation rung is removed (a session-less sandbox user routes to the connect flow); the stage branch and `auth_failed` derivation gain environment-`SANDBOX` extensions (sandbox authorization failures and mid-authorization reloads surface through the normal machinery); the state endpoint re-exports `environment` for the SPA's skip-linking branch. This deletes the session-less dashboard user class at the source.
- **Add-bank entry point (new)**: a permanent "Add bank" control on the dashboard re-enters the existing wizard at bank selection in client-side add-mode. No server-side mode exists — every dashboard user holds an `eb_sessions` row, so the resolver's stage branch is never consumable and any view position the flow persists is a dead letter: reload at any point abandons uniformly to the dashboard. Auth failure in add-mode surfaces as a dashboard notice via the existing one-shot `authError` signal (retry re-enters the flow; dismissal/retry clears the signal). Success reuses the existing chain unchanged (callback → merge → import signal → import step → dashboard).
- **Unified bank list + sandbox credentials (new)**: `GET /api/aspsps` fetches from the data-plane `GET /aspsps` whenever the EB application is active (the same list `POST /api/auth` validates against — a shown bank always connects), keeping the control-plane source only for the inactive-production outlier. For sandbox, the list is filtered server-side to sandbox-connectable banks (`sandbox` field or a small credential-less whitelist — Nordea, Mock ASPSP), carries the sandbox test credentials (`sandbox.users` — username/password/OTP per user) for the SPA's credentials panel, and suppresses production availability badges. The wizard gains a sandbox credentials panel (Tier 4 Info Box, per-field copy buttons, cleartext mono values, multi-user chips, credential-less variant) on BankSelection and AuthProgress, plus a public `/sandbox-credentials` popup route that keeps the credentials visible across the bank redirect (auto-opened from the Continue click, "Pop out" fallback, full edge-case matrix: missing params, unauthenticated, unknown bank, no-credentials, API failure — never an indefinite spinner, never echoed parameters).
- **Error-code-first failure classification (new)**: Enable Banking error bodies (`{code, error, detail}`) are parsed into `errorCode` on all data-plane `Error` result types and recorded in `sync_log.error_code`; classification keys on the error code, not the HTTP status (EB's own guidance). `EXPIRED_SESSION`/`REVOKED_SESSION`/`CLOSED_SESSION`/`SESSION_DOES_NOT_EXIST` mark the session consent-dead (re-authorization prompt, stored balances remain rendered — the retention principle: no local data loss, smooth contingency when a bank goes offline); `ASPSP_ERROR` stays transient-retryable; `ASPSP_RATE_LIMIT_EXCEEDED` stays `rate_limited`.
- **Vision alignment**: VISION.md is already updated (principle #4 reworded; §4.7 gains the manual-sync row) — this change implements that amended model.

## Capabilities

### New Capabilities

- `balance-sync`: The balances sync engine — trigger model (login, manual debounced refresh, background timer), PSU-header policy, per-run session-status refresh, balance persistence, sync log, SPA-triggered initial import with one-shot signal, and the sync status surfaced to the UI (last-updated, degraded states, in-flight flag).
- `account-overview`: The dashboard account overview — account cards, total balance with multi-currency grouping, per-bank last-updated badges, bank-scoped consent health, refresh affordance, the permanent add-bank control, empty presentations, and the visual state matrix (fresh, ambient in-flight, degraded/stale, consent attention, partial failure).

### Modified Capabilities

- `enable-banking-client`: Adds the data-plane `getBalances` and `getSession` requirements (`GET /accounts/{uid}/balances`, `GET /sessions/{id}`, optional PSU headers, sealed result types with nullable status codes); adds error-body parsing (`errorCode` on all data-plane `Error` types); the data-plane ASPSP listing gains the nullable `sandbox` field (`SandboxInfo`/`SandboxUser`) and nullable `errorCode` on its error type.
- `database`: Adds a migration requirement creating `balances`/`sync_log` (with `error_code` column) and extending `eb_sessions` with `valid_until`/`logo`, with deletion-path cleanup and the version-inference ladder fix.
- `spa-shell`: The "Welcome dashboard" requirement is replaced — the dashboard becomes the account overview (business data, refresh affordance) instead of a welcome message; the Purpose paragraph's "welcome dashboard" wording is adjusted at archive time. The public-routes requirement gains the fourth public route `/sandbox-credentials` (sole API-calling public screen, no theme toggle, in-window 401 handling).
- `onboarding`: The auth-callback success path persists `valid_until`/`logo` and sets the one-shot import signal; the auth-initiation endpoint stages the ASPSP logo URL; the wizard gains the SPA-triggered initial-import step; the dashboard gains the add-bank entry point (client-side add-mode, reload abandons to the dashboard, auth failure surfaces as a dashboard notice); sandbox onboarding requires account authorization (completion endpoint continues to the connect flow, state endpoint re-exports `environment`, BankSelection skips linking for sandbox); the bank listing endpoint switches to the data-plane source for active apps with sandbox filtering/credentials pass-through/status suppression; the wizard gains the sandbox credentials panel and the public `/sandbox-credentials` popup route (auto-open, Pop out fallback, edge-case matrix).
- `onboarding-view-position`: The route resolver's sandbox auto-activation rung is removed; the stage branch's `auth_progress` honoring and the `auth_failed` rung gain environment-`SANDBOX` extensions.

## Impact

- **`core/src/commonMain/sqldelight/`**: new `.sq` file(s) for `balances`/`sync_log` + a new `.sqm` migration (new tables + `eb_sessions` columns) + `DatabaseFactory` inference-ladder update.
- **`server/src/main/kotlin/`**: new sync engine (scheduler + sync runner + session-status refresh), `EnableBankingClient.getBalances`/`getSession` + error-body parsing (`errorCode` on all data-plane `Error` types) + `Aspssp.sandbox` parsing, new `/api/accounts`, `/api/sync`, `/api/onboarding/import-balances` routes, background-timer wiring in `Application.kt`, PSU-header extraction from real user requests, `mergeSession` signature extension (`valid_until`, `logo`), deletion-path cleanup, resolver changes (sandbox rung removal, stage/`auth_failed` environment extensions, `environment` re-export in the state endpoint), bank-list source switch (data-plane when active + sandbox filter/credentials pass-through/status suppression).
- **`app/web/src/commonMain/kotlin/`**: `DashboardScreen` rewritten as account overview (incl. the "Add bank" control), `AppViewModel` gains dashboard data state (accounts, balances, sync status, in-flight polling) and client-side add-mode state, onboarding wizard gains the import step (one-shot signal consumption) and add-mode entry at bank selection, dashboard auth-failure notice for add-flow failures, sandbox connect flow (skip ActivationGuide after registration, skip linking at bank selection), sandbox credentials panel (BankSelection + AuthProgress placements, multi-user chips, credential-less variant), public `/sandbox-credentials` popup route (auto-open from Continue, Pop out fallback, edge-case presentations).
- **External API usage**: Enable Banking `GET /accounts/{uid}/balances` and `GET /sessions/{id}` (new data-plane calls; PSU headers optional per EB docs).
- **No breaking changes** to existing endpoints or flows; the wizard import step is additive and its failure is non-blocking (continue-anyway).
